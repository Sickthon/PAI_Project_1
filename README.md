# Air Pollution Prediction with Gaussian Process Regression

Predicting PM2.5 concentration over a 2D city map using Gaussian Process (GP) regression, with a focus on scalable fitting (~15,000 training points) and well-calibrated predictions in candidate residential areas.

## Problem

Given noisy PM2.5 measurements at known map locations, predict pollution at unseen locations.

| File | Description |
|---|---|
| `train_x.csv` | Training features: relative 2D coordinates `(x, y)` and a binary flag marking whether the point lies in a candidate residential area |
| `train_y.csv` | Noisy PM2.5 measurements (µg/m³) for each training location |
| `test_x.csv` | Test features, same format as `train_x.csv` |
| `test_y.byte` | Held-out test targets used by the evaluator |
| `solution.py` | Solution template containing the `Model` class |

The required interface in `solution.py`:

- `Model.fit_model(train_x, train_y)`: fit the GP
- `Model.predict_pollution(test_x)`: return predictions for the test locations
- `get_city_area_data(...)`: data preprocessing wrapper

The method signatures must not change, since the evaluation script relies on them. The `main()` function in the template is for illustration only and is ignored by the checker.

## Exploratory Data Analysis

Key observations from the plots (see `eda_plots.py` and the notebook):

- **Even spatial coverage.** Samples fill the unit square densely with no large gaps.
- **Residential candidates are disks.** The flag is a function of location only: circular patches of various sizes, some overlapping.
- **PM2.5 is not a smooth field.** High values form thin, ridge-like filaments, many roughly axis-aligned, with a broad low-pollution region in the bottom-left corner. The ridges cross residential boundaries, so the flag alone is a weak predictor of PM2.5.
- **Measurement noise is visible.** A few readings are slightly negative, which a true concentration cannot be.

These findings motivate a rough, multi-scale kernel rather than a single smooth RBF.

## Approach

### Model

A `GaussianProcessRegressor` from scikit-learn with a compound kernel:

```python
kernel = (C(1.0) * Matern(length_scale=[0.3, 0.3], nu=1.5)     # broad regional trend
          + C(1.0) * Matern(length_scale=[0.03, 0.03], nu=1.5)  # fine-scale ridges
          + WhiteKernel(noise_level=0.1))                       # measurement noise
```

- **Matérn** kernels fit sharp features better than RBF, which over-smooths.
- **Two length scales** capture both the large cold region and the narrow ridges.
- **ARD** (separate x and y length scales) allows for axis-aligned structure.
- **`WhiteKernel`** learns the measurement noise from the data.
- `normalize_y=True` makes the zero-mean prior assumption reasonable.

### Scaling to 15,000 points

An exact GP needs O(n³) time and O(n²) memory, which is too heavy for n = 15,000. The strategy:

1. Select a subset of points (spatially spread via k-means, or a contiguous window to preserve short-range structure).
2. Learn the kernel hyperparameters on this subset by maximizing the log marginal likelihood.
3. Refit on a larger set of points with the hyperparameters frozen (`optimizer=None`), which needs only a single Cholesky factorization.
4. Predict in chunks to limit memory use.

Local GPs (one per region, with overlapping borders) are a possible alternative, since the short correlation lengths mean distant points barely influence each other.

### Residential areas

The flag is determined by location, so adding it as an input feature gives the GP little information. Any asymmetric treatment of residential areas (for example, shifting predictions upward by a multiple of the predictive standard deviation if underestimation is penalized more heavily) is applied at prediction time.
